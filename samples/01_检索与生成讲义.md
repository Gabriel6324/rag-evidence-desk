# 检索与生成讲义
这是一份为软件演示编写的虚构课程资料，不代表真实学校的教学要求。

## RAG 的基本流程
RAG 先从外部资料中检索证据，再将问题与证据一起提供给语言模型生成回答。资料入库通常包括文本提取、切分、向量化和写入向量数据库；提问时则需要完成查询向量化、候选片段召回、证据筛选和带引用回答。向量数据库存储的是向量以及来源信息，不能直接判断一段答案是否正确。资料中的页码、章节和字符位置应当在提取时保留，而不是在生成后猜测。回答者需要区分资料明确陈述的事实和根据多个条件推导出的结论；推导应列出条件，不能把常识当作课程规定补进去。
检索增强生成并不会自动消除幻觉。即使召回到了正确文档，也可能遗漏文档内的关键限制条件；即使引用编号存在，结论也可能超出原文支持范围。因此，项目评测应分别检查检索、引用和答案是否有证据支持。检索失败与生成失败要分开记录，避免把所有错误归为模型能力不足。对于资料未说明的问题，明确承认证据不足比生成听起来合理的答案更可靠。

## chunk 大小与重叠
chunk 是参与检索的文本片段。本课程实验中的 chunk_size 以字符数计量，不是模型 token 数量。较小的 chunk 通常使证据更集中，但容易拆开条件与结论；较大的 chunk 保留更多上下文，却可能把无关信息一起送入模型。overlap 表示相邻切片重复的字符数，用于减少边界处的信息丢失。切片不跨 PDF 页或 Markdown 章节，以便保留可靠的来源位置。同一知识点的重复切片应去重，避免 top-k 被相似文本占满。不要根据一两个问题选择最优参数，需要使用同一组带标注的问题比较不同配置。
实验建议至少比较 240、420、700 字符的切片长度，并固定重叠比例或明确记录固定重叠值。若片段长度改变，必须重建向量索引；只改变 top-k 不需要重建索引。为了复现，应记录切分策略、嵌入模型、资料版本、数据集哈希和参数。对于中文文本，字符长度仅是近似的成本控制方式，不能替代服务商的 token 计费统计。若问题需要跨片段推理，应检查所有必要证据是否都在最终上下文中，而不是只看第一条检索结果。

## 向量检索与混合检索
Embedding 将文本转换为固定维度的向量，语义模型训练出的向量可以用于语义相似度检索。演示用的 n-gram 特征哈希只编码词面特征，不能视为训练好的语义模型。余弦相似度用于比较向量方向，但不是答案正确的概率。BM25 根据词项频率、逆文档频率和文档长度计算词面相关性。混合检索同时使用向量检索与 BM25，可以补充课程编号、变量名或精确术语等词面线索。
RRF 使用候选在不同排序列表中的名次进行融合，不直接相加 BM25 与余弦分数。它的形式是对各列表中的 1/(常数加名次) 求和，本项目的常数取 60。top-k 指最终进入回答上下文的片段数量。增大 top-k 可能补全证据，也可能引入噪声和增加模型输入成本，不能保证准确率持续提高。用问题拆分产生多个检索子句时，仍需去除重复片段，确保每条最终证据都有可追溯来源。

## 评测与引用
检索命中率衡量至少一个标注证据是否被召回；完整证据率要求所有必要证据都被召回。证据召回率按照每道题所需证据单元的覆盖比例计算，再对题目取平均。引用编号有效只说明编号指向一个已召回片段；引文匹配只说明引文确实出现在片段中。两者都不能单独证明答案正确。复杂推理题应人工核对结论是否由全部证据共同支持。
