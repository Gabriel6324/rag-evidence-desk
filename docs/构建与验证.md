# 构建与验证

## 环境和自动检查

推荐 Python 3.12。`requirements.txt` 固定直接依赖；`requirements-lock.txt` 保存交付环境的依赖版本，并包含平台标记。Windows 运行包使用 Windows CPython 3.12.10 和 Windows x64 依赖，不把 Linux 动态库放入运行包。

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m compileall -q rag desktop.py desktop_settings.py desktop_help.py tests
```

浏览器检查需额外安装 Playwright，不进入应用运行依赖：

```bash
python -m pip install playwright==1.51.0
python -m playwright install chromium
python tests/ui_smoke.py
python tests/ui_history_paging.py
```

脚本在同一个进程环境启动临时服务和浏览器，使用临时数据，测试帮助、模型设置、引用、Agent、上传、失败提醒、离线评测和窄屏布局；输出放在项目外的 `qa-browser`，可用 `RAG_UI_QA_OUT` 指定。`RAG_BROWSER_BIN` 可指定已有 Chromium 可执行文件。API 错误场景使用固定模拟响应；不调用付费模型。

`ui_history_paging.py` 使用独立临时数据建立 42 条历史记录，模拟另一页面新增一轮离线评测后继续加载历史，检查最新记录与全部 43 条记录均可查看，加载按钮不会陷入重复页循环。它不改动日常资料或调用付费模型。

## 发行打包

```bash
python scripts/package_release.py --out dist
python scripts/package_release.py --windows-base /path/to/ZhiJuEvidenceDesk --out dist
```

第一条生成源码包。第二条还生成 Windows 包，基础目录必须包含完整、验证过的 Windows `runtime` 和 `ZhiJuEvidenceDesk.exe`。脚本沿用基础包的 Windows 运行时与启动器，将当前应用和正常使用说明放入新包，不继承基础包的其他文档或用户数据。

当前 Windows 包沿用 1.2.0 的原生启动器，SHA-256 为 `bf374b7822d051373542734e78a8c4631e08f5a7cdccc11317c707ba0dbe7db3`。启动器负责运行同目录下的 `runtime/pythonw.exe desktop.py`；界面、设置及服务行为在 Python 代码中更新。不能把包装器的版本当作应用版本。

打包使用文件允许清单；排除 `.env`、用户资料、诊断、缓存、私人材料及测试截图。公开技术和内置离线评测记录可以保留。Windows 依赖清单和二进制架构可静态校验；实际启动、保存后的重启和窗口布局需要真实 Windows 环境验证。

## 容器

```bash
docker build -t zhiju-evidence-desk:1.2.3 .
docker run --rm -p 127.0.0.1:8765:8765 -v zhiju-data:/data zhiju-evidence-desk:1.2.3
```

访问 `http://127.0.0.1:8765`。配置和数据保存在命名卷中；容器内不使用原生窗口，模型设置在工作台保存并应用。端口只绑定宿主机回环地址。项目没有公网账户认证，不应直接公开到互联网。

`.github/workflows/ci.yml` 包含 Windows/Linux Python 3.12 的安装、单元测试和语法检查，并在 Linux 运行浏览器检查。每次提交的实际验证结果请查看 GitHub Actions。自动检查不包含 Windows 桌面实机和 Docker 部署验收。
