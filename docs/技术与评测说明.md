# 技术与评测说明

知据把资料召回与回答生成分开：先找到可以查阅的证据，再组织答案并核对引用。主要观察跨片段问题的证据完整性，以及必要信息缺失时能否合理拒答。

## 资料和位置

PDF 按页提取，Markdown 按标题分段，TXT 保留文本位置，DOCX 提取段落和表格行。片段保留文档、位置、文本单元与 `[start, end)` 字符范围。范围基于标准化的提取文本，方便原文窗口高亮；不是原始文件字节偏移。切分和上下文预算按字符计算，不是 token 计费估算。

## 向量、索引与检索

默认特征哈希使用中文二字组、英文词项、确定性 BLAKE2 哈希、对数词频及归一化。它用于离线流程验证，不等同于语义 Embedding。

API 模式按批发送文字，按响应 index 恢复顺序，并检查数量、维度、有限值与零向量。缓存键为模型配置指纹加文字 SHA-256；更换模型或地址不会复用旧配置缓存。

向量存储在 Qdrant，原文、片段快照和元数据保存在 SQLite。默认 Qdrant 本地持久化，也可使用配置的服务端。重建先建立新集合，完整写入并保存元数据后才替换活动索引；失败保留旧索引。资料修订、向量配置与数据库位置都参与过期判断。删除本地旧集合前显式关闭存储句柄，避免 Windows 文件占用。评测使用独立内存 Qdrant，其余临时数据在关闭资源后清理。

向量与 BM25 分别召回，RRF 使用 `Σ 1/(60 + rank)` 融合排序。复合问题可规则拆分为最多 4 个查询；按选定资料范围检索，排除标记的可疑片段，去除高度重叠证据，再取 top-k。

最低余弦阈值通常过滤所有候选。开启“保留明确术语命中”时，混合检索中有 BM25 命中、且包含问题中全部明确英文标识词的片段可绕过该阈值；返回结果标注是否发生术语补召回。这是受约束的词面补召回，不是通用语义理解。

可选重排请求当前 Rerank API，对扩展候选重新排序；响应要通过编号、数量和分数校验。连接失败时保留原排序，运行详情展示降级原因。它是外部模型重排接口，不是项目自行训练的 Cross-Encoder。

## 生成、证据筛选与引用

默认摘录模式选择相关原句；启用离线证据筛选后，会针对资料缺字段、必要条件缺失等已实现模式保持回答边界。该规则只适用于其覆盖的问题形式，不能代表任意问题都能判断证据是否充分。

LLM 接收问题、有限的会话上下文与本次证据。它必须返回规定的 JSON，结论附带 evidence ID 和逐字 quote。展示前检查结构、引用编号及引文是否存在于对应原文；失败会报错，不展示未经校验的回答。

这些检查验证来源和摘录，不能证明原文在逻辑上支持结论。实际业务中的事实正确性、条件推理和冲突处理仍需独立评审。

## Agent、会话和追踪

LangGraph 编排决定、工具、回答三个阶段。模型 Agent 使用兼容 Tool Calling 的对话模型；离线演示沿同一图使用规则规划。内部工具仅为 `search_documents` 和 `read_source`，严格校验参数、资料范围及已取得的证据编号，最多 4 轮决策、6 次工具调用。只展示最终经引用校验的回答与工具动作，不展示或保存自由形式的中间思考文本。

SQLite 保存会话和每次回答的证据快照。模型上下文取最近 3 回合并限制到 1600 字符；短追问使用规则补足检索问题，历史回答不作为新答案的事实证据。这里没有长期记忆、自动摘要或跨进程恢复 Agent 中途状态。

会话数量上限为 200，每个会话保留最近 100 次问答及证据。独立运行追踪保留最近 200 条，列表返回最近 50 条；删除会话会删除其问答记录，不删除独立追踪或评测记录。评测记录保存在同一 SQLite 数据库，写入或提交失败会回滚，避免后续操作提交失败任务的残留记录。旧报告只有通过结构与指标校验后才恢复，异常文件原样保留。

运行追踪记录阶段耗时、候选及上下文数量、缓存、重排、工具次数和终止原因。token 用量来自平台响应，未返回时不编造；本机字符预算不作为实际账单。

MCP 使用官方 SDK 的 Streamable HTTP，提供 `list_documents`、`search_documents`、`read_source`。工具只读、输出结构化，客户端和 Agent 工具的范围分别受校验。

## 配置与失败诊断

网页与原生窗口使用同一设置存储，提供分类型测试、模型列表和共享帮助。Key 仅保存在本机，不回填网页；网页使用文本输入加视觉遮罩，避免被当成新登录密码。Windows 保存设置会请求原生服务重启；普通源码服务直接应用配置。正在运行的任务与配置修改互斥，避免中途更换模型。

每个后台任务保留最后执行阶段。失败诊断区分模型 HTTP 状态、网络、系统权限、资源占用、文档解析、索引、Agent、输入及评测等情况，并给出相应步骤。诊断遮挡已知 Key、Bearer 和常见凭证格式，不公开原始模型错误正文。未知故障保留类型、阶段及代码位置，同时明确原因未确定。诊断写入失败不会替换原故障。

前端失败提醒跨页面保留，右侧详情打开对应引导，X 关闭同一条提醒；新错误仍显示。原生窗口提供相同诊断内容。

## 已实现的边界控制

部分角色覆盖、系统提示和密钥索取模式会标记并隔离；字符串筛查可能漏检或误伤。前端把上传文字和模型文字作为文本展示，不执行其中 HTML。模型 HTTP 不自动跟随重定向；本机服务检查 Host、Origin、请求大小，设置 CSP。系统没有多用户账号或公网身份认证。

## 标注与指标

内置 18 题使用虚构资料：14 道有答案题，其中 5 道多证据题；4 道应拒答题包括资料外问题、缺字段、条件不足和注入请求。每道题包含唯一 id、question、type、evidence 和 keywords；每个证据包含来源文件名及连续原文 quote。无充分证据的问题以空 evidence 标注。自定义题库需为 UTF-8 有效 JSON，来源及引文必须匹配。

| 指标 | 定义 | 解释边界 |
| --- | --- | --- |
| hit@k | 有答案题中至少一个标注证据被完整召回的占比 | 不是答案正确率 |
| 证据召回率 | 每道题召回证据原子数 / 必要原子数，再宏平均 | 只覆盖当前人工标注 |
| 完整证据率 | 所有必要证据均找全的有答案题占比 | 找全不代表推理正确 |
| 多证据完整率 | multi 题中所有证据找全的占比 | 不是通用多跳能力 |
| MRR | 第一条包含标注证据的结果排名倒数，再平均 | 不是生成质量 |
| 引用编号有效率 | 有效编号数 / 实际展示引用数 | 不评价引用相关性 |
| 引文匹配率 | 原文中能逐字找到的引文 / 展示引文 | 不证明语义支持 |
| 应拒答题拒答率 | insufficient 的应拒答题 / 所有应拒答题 | 不代表通用安全率 |
| 有答案误拒数 | 有答案题中被判 insufficient 的数量 | 与拒答率一起看 |
| 关键词覆盖 | 预设关键词在答案中的出现比例 | 仅为诊断，不是正确率 |

没有分母时输出 null。回答先通过引用校验，展示引文匹配率可能一直为 100%，这是流程检查，不是独立质量评审。模型格式错误会终止评测并明确报错。

## 参数对照与四组消融

对照使用 chunk 240 / 420 / 700、top-k 3 / 5、vector / hybrid，共 12 组；overlap 60，阈值 0.08，规则拆分开启。四组消融固定 chunk 240、top-k 3、hybrid，分别开关术语补召回与离线证据筛选。数据和参数固定后比较完整证据率、拒答与误拒，不能把变化归因于真实模型能力。

本次内置四组结果：原始完整证据 13/14、边界正确拒答 2/4、有答案误拒 1；两项优化为 14/14、4/4、0。两项单独结果和逐题失败案例见 [四组记录](../reports/ablation.md) 与同名 JSON。

报告记录题库及资料 SHA-256、时间、依赖版本、模式、参数和逐题响应。延迟受机器及缓存影响。题库与演示共享合成资料，不能作为独立泛化测试。真实语义模型、真实业务资料、改写问题、攻击变体和人工语义标签需要另行评估。
