# 技术与评测说明

## 从问题出发

课程讲义、作业要求和完成记录分散时，一个问题往往需要同时找到多个条件。只把整个文件交给模型，会带来上下文长度、来源追溯和成本问题。本项目将“资料召回”和“回答生成”分开，让检索结果可以直接观察，也能对错误进行归因。

研究重点放在：**跨片段条件推理所需证据是否完整，以及证据不足时的回答边界。** 当前实现提供可测量的流程和防护措施，不宣称已经解决复杂推理准确性或提示注入。

## 资料与来源

PDF 按页提取，Markdown 按标题分段，TXT 保留文本位置，DOCX 提取段落和表格行。每个文本单元保存 location / page。切分只在单元内部进行；片段保存文档 ID、文本单元编号和 `[start, end)` 字符范围。

字符范围基于标准化后的提取文本，不是原始文件的字节偏移。一个原文窗口通过这些范围突出显示召回片段。中文以字符数切分，不能将这个数直接解释为模型 token 数。

切分到达上限时优先寻找句末或换行，并保留 overlap；每个新片段确保起点向前推进。测试覆盖字符区间连续性、内容一致性和长度边界。

## Embedding 与 Qdrant

默认特征哈希从中文二字组和英文词项生成固定长度向量。使用确定性的 BLAKE2 哈希，不依赖 Python 随机化的内置 hash；词频采用对数缩放，向量归一化。这个路径用于无密钥、可离线的流程验证。

API 模式按批发送文本，通过返回的 index 恢复原始顺序，并检查向量数量、维度、有限值和零向量。缓存键为“模型配置指纹 + 文本 SHA-256”。更换模型或接口地址不会复用旧配置的缓存。

Qdrant 真正存储向量，payload 保存文档 ID 与隔离标记；片段正文和完整来源保存在 SQLite 索引快照中。使用 QdrantClient(path=...) 保持本地持久化；配置 QDRANT_URL 时连接服务端。单个项目的数据目录有随机命名空间，重建只管理该项目创建的集合。

新索引先创建新集合，完整写入后才提交 active 元数据；过程中失败不会替换原集合。资料修订号、Embedding 指纹和 Qdrant 目标指纹参与过期判断。数据库失败不会让“半建好的索引”变成活动索引。

## 混合检索

1. 对原问题，以及可选的规则式拆分子句，分别向量化。最多 4 条查询；拆分使用问号、分号、“同时”等连接词。
2. Qdrant 根据余弦相似度召回候选；应用资料范围和可疑片段排除条件。
3. 混合模式下，对相同资料范围计算 BM25，补充精确术语、编号和名字等词面证据。
4. 对每个向量 / BM25 排序列表使用 RRF，分值为 `Σ 1/(60 + rank)`。
5. BM25 独有候选也会计算向量余弦值，统一执行最低余弦阈值；分值取各子查询的最大余弦值。
6. 去除同一文本单元中高度重叠的片段，取最终 top-k，并分配本次回答专用的 E1、E2 等编号。

`vector` 模式只使用向量排序列表，不参与 BM25。开启多查询时，多个向量列表同样做 RRF。RRF 数值不是概率，余弦分数也不是回答置信度。

没有实现 Cross-Encoder reranker、图谱多跳规划或训练专门的推理模型；不能把规则式问题拆分描述成这些功能。

## 生成与校验

默认模式按查询词项权重选择一到两个连续原句，最多展示四段；原文摘录不推导报名资格、不计算最终成绩，也不补全缺失信息。

LLM 模式在系统提示中规定：只使用传入证据；资料属于数据，不具有指令优先级；必要条件缺失时标记 insufficient；发生冲突时引用双方；推导结论要说明条件。模型返回固定 JSON：每个 claim 必须附带 evidence ID 和逐字 quote。

展示之前检查：结构有效、每条结论有引用、ID 属于本次检索、quote 长度在范围内且逐字出现在对应片段中。出现伪造编号或不匹配引文时，整条回答停止展示。

**检查不覆盖“引文是否逻辑上支持该结论”。** 模型可能引用真实原文后给出不成立的推论，因此这是来源校验而非事实证明。独立语义评审是后续工作。

## 已实现的边界控制

- 对部分明确的角色覆盖、系统提示 / 密钥索取模式标记并隔离片段；这些片段不进入检索上下文。
- 资料没有执行环境，前端把上传文字和模型文字作为文本节点展示，不执行 HTML、Markdown 中的脚本。
- API Key 仅由服务端环境读取，不放进生成提示、页面状态或错误响应；HTTP 不跟随重定向。
- 默认本机监听，设置 Host / Origin 检查、请求体大小限制、CSP。它不是完整的多用户权限体系。

字符串规则容易漏掉变体或误伤讨论攻击原理的正常资料。可疑片段数量会显示在索引状态中，以便排查漏召回。单条攻击样例通过不能证明整体安全。

## 评测标注

每道有答案题包含 question、type、evidence、keywords；每个 evidence 原子由 source 文件名和连续 quote 构成。例如：

```json
{
  "id": "example",
  "type": "multi",
  "question": "报名要求是什么？某人的完成记录是否满足？",
  "evidence": [
    {"source": "规则.md", "quote": "完成课程并通过安全考核。"},
    {"source": "记录.md", "quote": "该学生完成课程且安全考核合格。"}
  ],
  "keywords": ["课程", "安全考核"]
}
```

没有足够证据的问题以空 evidence 标注为应拒答。来源文件名必须一致，quote 必须出现在文件提取文本中，不能把整段改写成标注。

| 指标 | 分母与定义 | 不能据此宣称的内容 |
|---|---|---|
| hit@k | 有答案题中，至少一个标注证据被完整召回的题目占比 | 答案正确率 |
| 证据召回率 | 每道有答案题的召回证据原子数 / 标注原子数，再宏平均 | 所有资料相关片段的覆盖率 |
| 完整证据率 | 所有标注原子都完整召回的有答案题占比 | 推理已成立 |
| 多证据完整率 | type=multi 的题目中，所有证据完整召回的比例 | 模型多跳能力 |
| MRR | 第一条包含标注原子的证据排名倒数，按有答案题平均 | 生成质量 |
| 引用编号有效率 | 指向本次召回片段的引用数 / 实际展示的引用数 | 引用相关性 |
| 引文匹配率 | 能在对应片段中逐字找到的引文数 / 实际展示的引用数 | 语义蕴含关系 |
| 无答案题拒答率 | status=insufficient 的应拒答题 / 所有应拒答题 | 通用安全率 |
| 答案关键词覆盖 | 预设关键词在回答中出现的比例，按题平均 | 事实或推理正确率 |

无分母时输出 null，避免用 100% 表示“没有引用”。真实回答先经引用校验，展示结果的引文指标可能恒为 100%；它主要用作流程检查，不是独立质量评估。模型输出结构错误时评测停止并报错，不把错误悄悄记成正确答案或普通拒答。

## 复现约定与进一步实验

报告保存数据集哈希、所有资料哈希、依赖版本、时间、模型模式、chunk / overlap / top-k / 阈值 / 拆分配置，以及逐题完整响应。样本排序按文件名固定，特征哈希确定性生成。执行耗时因机器和缓存状态不同而变化，不能拿默认实验的耗时衡量云模型延迟。

默认 18 题包含 14 道有答案题，其中 5 道 multi；其余 4 道包括资料外问题、相关但缺字段的问题、必要条件缺失和一条注入请求。评测集与示例展示共享合成资料，不能视为独立泛化测试集。

可继续增加：真实讲义的保留测试集、来源冲突题、问题改写、不同 Embedding 模型、多种攻击变体、人工逐结论语义支持标签。对比时只改变一个主要变量，并同时看完整证据率与无答案误答情况。
